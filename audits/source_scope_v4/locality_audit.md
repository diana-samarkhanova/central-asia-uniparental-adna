# B10 — locality-string audit (public summary)

Audit date: **2026-08-21**

The audit was performed on the frozen, source-derived working catalogue. That
catalogue and its exact locality strings remain outside the public repository.
This file reports the audit logic and aggregate outcome without publishing a
locality crosswalk, exact site names, or coordinates.

## Automated checks

| Check | Result |
|---|---:|
| Unique persons/rows inspected | 501 |
| Distinct raw locality strings | 141 |
| Distinct canonical locality strings | 140 |
| Canonical localities with more than one raw spelling | 1 |
| Leading/trailing whitespace | 0 |
| Double spaces | 0 |
| Unbalanced parentheses | 0 |
| Unicode/apostrophe-only duplicate collisions after NFKC, case-folding and punctuation removal | 0 |

The reduction from 141 raw strings to 140 canonical strings represents one
verified one-letter spelling alias in Kazakhstan, affecting two AADR-derived
records. The decision was checked against the administrative description and
coarse spatial metadata. The source and canonical strings, coordinates and
source person identifiers are intentionally withheld from this public summary.

## Candidate review

Potential matches generated by lexical similarity or identical rounded
coordinates were reviewed manually. Twelve candidate families were retained as
distinct because at least one of the following differed or remained
unresolved: numbered cemetery or site designation, grave/object number,
settlement versus cemetery context, excavation sector, administrative unit,
chronology, archaeological group, or source-publication context.

No additional merge was justified from the frozen metadata. In particular,
rounded coordinates were treated only as coarse centroids and never as
sufficient evidence that two named archaeological entities were identical.

## Analysis-safe implementation rule

The cluster-aware analyses use the reversible private tuple `(country,
canonical locality)`. The working catalogue retains the unmodified source
string in `locality_raw`, and a version-controlled private alias dictionary
contains only archaeologically verified equivalences. Punctuation, case and
Unicode normalization may create candidate keys for review but cannot itself
merge records. Numbered suffixes, grave numbers, settlement/cemetery
qualifiers and excavation-sector labels remain semantically meaningful.

The public analytical input replaces locality strings with deterministic
project site codes. It therefore supports exact rerunning of the released
models without exposing the source locality crosswalk.
